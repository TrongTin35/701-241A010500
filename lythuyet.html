Câu 1: Khác biệt giữa position: relative và position: absolute (10 điểm)

Khác biệt chính:

  • position: relative: Phần tử vẫn nằm trong luồng dịch chuyển tự nhiên (normal document flow) của trang. Các thuộc tính top, right, bottom, left sẽ dịch chuyển phần tử dựa trên vị trí ban đầu của chính nó mà không làm xô lệch các phần tử xung quanh.
  • position: absolute: Phần tử bị kéo ra khỏi luồng dịch chuyển tự nhiên (out of flow). Nó sẽ định vị tương đối dựa theo phần tử cha gần nhất có position khác static. Nếu không có, nó sẽ căn theo thẻ <body> hoặc khung nhìn.

Ví dụ tình huống Responsive Layout:

/* Card sản phẩm có badge "Giảm giá" ở góc */
.product-card {
    position: relative; /* Thẻ cha làm mốc định vị */
    width: 100%;
    max-width: 300px;
}
.badge-sale {
    position: absolute; /* Thẻ con định vị tuyệt đối theo .product-card */
    top: 10px;
    right: 10px;
}

Ảnh hưởng khi Deploy & Responsive: Cần cẩn trọng khi dùng absolute với kích thước cố định (px) vì khi mở trên thiết bị màn hình nhỏ (mobile), phần tử có thể đè lên chữ hoặc tràn khung (overflow). Nên kết hợp Flexbox/Grid cho khung tổng thể và chỉ dùng absolute cho các chi tiết nhỏ gắn liền với thẻ cha (như badge, icon, button đóng modal).

Câu 2: Quy trình Đăng ký Domain, Hosting & Security (10 điểm)

Quy trình đăng ký và cấu hình:

  1. Chọn & Mua Domain: Đăng ký tên miền qua nhà cung cấp (Namecheap, GoDaddy, Pawnhost, v.v.).
  2. Thuê/Tạo Hosting: Sử dụng Hosting dịch vụ hoặc các nền tảng Static Hosting (GitHub Pages, Netlify, Vercel).
  3. Cấu hình DNS: Trỏ bản ghi (A Record chỉ về IP của Hosting, hoặc CNAME Record trỏ về tên miền của dịch vụ hosting).

Vai trò của DNS (Domain Name System): Đóng vai trò như "danh bạ Internet", dịch chuyển Tên miền dạng chữ mà con người dễ nhớ (ví dụ: example.com) thành địa chỉ IP dạng số mà máy tính sử dụng để kết nối (ví dụ: 192.0.2.1).

2 Công cụ Deploy không cần Server riêng:

  • GitHub Pages: Tích hợp sẵn với kho lưu trữ GitHub, hoàn toàn miễn phí cho trang web tĩnh HTML/CSS/JS.
  • Netlify: Hỗ trợ CI/CD kéo thả trực tiếp file hoặc kết nối Git, hỗ trợ SSL miễn phí tự động.

Rủi ro bảo mật nếu cấu hình sai:

  • Chưa kích hoạt HTTPS (thiếu chứng chỉ SSL/TLS): Dữ liệu truyền đi không được mã hóa, dễ bị tấn công Man-in-the-Middle (MITM).
  • Sai cấu hình CORS hoặc lộ API Key nhạy cảm trong code client JS công khai.

Câu 3: So sánh let, const, var; Hoisting và Debug (10 điểm)

Đặc điểm var let const
Scope Function Scope Block Scope {} Block Scope {}
Khai báo lại Có Không Không
Gán lại giá trị Có Có Không (Hằng số)
Hoisting Có (Khởi tạo là undefined) Có (Nằm trong Temporal Dead Zone - TDZ) Có (Nằm trong Temporal Dead Zone - TDZ)

Ví dụ lỗi thường gặp do Hoisting / TDZ:

// Sử dụng let trước khi khai báo
console.log(age); // Lỗi: Uncaught ReferenceError: Cannot access 'age' before initialization
let age = 20;

// Lỗi biến var trong vòng lặp bất đồng bộ
for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 1000); // In ra: 3, 3, 3 (do biến i dùng chung function scope)
}

Cách Debug bằng Chrome DevTools:

  1. Mở DevTools (Phím F12 hoặc Ctrl+Shift+I) -> Chuyển sang tab Sources.
  2. Mở file JS, nhấn vào số dòng code để đặt Breakpoint (Điểm dừng).
  3. Thực thi thao tác trên trang web, code sẽ dừng tại Breakpoint. Sử dụng bảng Scope bên phải để quan sát giá trị biến và kiểm tra luồng chạy từng bước bằng nút Step over / Step into.

Câu 4: Event Delegation trong JavaScript (10 điểm)

Khái niệm: Event Delegation (Ủy quyền sự kiện) là kỹ thuật tận dụng cơ chế **Event Bubbling** (Sự kiện nổi bọt từ phần tử con lên phần tử cha) bằng cách gắn 1 sự kiện duy nhất lên thẻ cha để quản lý tất cả các phần tử con (kể cả các phần tử được thêm động vào DOM sau này).

Ví dụ ứng dụng cho Dynamic List:

// Thẻ cha <ul id="myList"></ul>
document.getElementById('myList').addEventListener('click', function(e) {
    if (e.target && e.target.nodeName === 'LI') {
        console.log('Bạn đã click vào item:', e.target.innerText);
    }
});

Lợi ích tối ưu hiệu suất: Giảm thiểu bộ nhớ (Memory Consumption) và cải thiện tốc độ xử lý do không phải đăng ký quá nhiều Event Listener cho từng phần tử con. Giúp code gọn gàng, tránh memory leak khi thêm/xóa thẻ động.
